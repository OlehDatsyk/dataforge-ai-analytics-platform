# Data privacy

This describes how DataForge AI handles your data as implemented. If you deploy it for others, you are responsible for your own legal obligations, such as GDPR.

## Where data is stored

| Data | Location | Protection |
|---|---|---|
| Original uploads | `DATA_DIR/workspaces/<workspace>/datasets/<dataset>/original/` | Generated file names, path checks, and backend authorisation |
| Processed versions | Parquet files under `.../versions/` | As above |
| Metadata, column statistics, category labels | SQL database | Workspace checks |
| Analyst answers and reports | SQL database, including aggregated results | Workspace checks; conversations are also private to their author |
| Connection credentials | SQL database | Encrypted with `ENCRYPTION_KEY` |
| Passwords | SQL database | Argon2 hashes |
| Session and reset tokens | SQL database | SHA-256 hashes |

Stored profiles include frequent values from your data, and reports include result rows. Treat the database as sensitive, not only the files.

**Dataset files are not encrypted by the application.** Use an encrypted disk or volume where this matters.

## Isolation

Every request is authorised on the server against workspace membership. A record in another workspace returns 404, and doesn't reveal that it exists. Automated tests cover this for datasets, rows, exports, cleaning, charts, conversations, scans, reports, and saved visualisations.

Workspace roles control what members can do. Conversations stay private to their author, even within a shared workspace.

## What is sent to AI providers

**In demonstration mode, nothing leaves the server.**

With a live provider configured, each question makes up to two requests:

| Request | Contents |
|---|---|
| Planning | The dataset name and row count, column names and types, date ranges, the question, recent questions and direct answers in the conversation, and up to 15 frequent labels per category column (each up to 80 characters) |
| Explanation | The question, calculation description, filters, time range, row count, engine summary, and up to 40 **aggregated** result rows |

**Raw dataset records are not sent.** But aggregated results can still be sensitive, and they carry labels. A grouped result could show a customer's name if you group by customer. Column names can be sensitive too.

For an anomaly question, the explanation request includes the findings table, which can contain individual observed values and row numbers.

To reduce exposure:

- Set `AI_SHARE_CATEGORY_VALUES=false` to withhold category labels. Filters on specific values may become less accurate.
- Use `AI_PROVIDER=demo` to keep everything local.
- Review your provider's data retention and training terms before using sensitive data.

Each analyst answer states what was shared, under **How this was calculated**. The **AI and privacy** settings tab shows the active provider.

## External connections

A data connection copies data into DataForge AI, once, when you choose **Import**. Credentials go only to the server you configured. Redirects to a different host don't receive your secret header.

## Logs and audit trail

- Application logs record error types and request paths, not dataset contents, and not exception messages that could contain cell values.
- The audit log records actions, identifiers, counts, and IP addresses. It doesn't store question text or data values, though it does store dataset names when datasets are deleted.
- The API returns generic error messages, without internal paths.

## Retention and deletion

Nothing is deleted automatically. Deleting a dataset removes its files and derived records, including charts, scans, reports, and conversations. Deleting a workspace removes everything in it. Audit log entries about deleted datasets remain until the workspace is deleted. There is no self-service account deletion yet, so an administrator must remove accounts from the database.

Deleted files may remain in backups or in a synced folder's version history.

## Sample data

Everything in `sample_datasets/` is generated by `backend/scripts/generate_sample_datasets.py` from a seeded random generator. Product and merchant names are invented, and countries are the only real-world labels. Screenshots use only this data and a placeholder account.
